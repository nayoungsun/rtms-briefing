# 실거래 등록 브리핑

서울 25개 구와 용인·수원·성남·과천·광명의 아파트 매매 실거래 중,
**국토교통부 공개시스템에 어제 새로 등록된 건**만 골라 매일 아침 리포트로 만듭니다.

GitHub Actions가 매일 06:30(KST)에 자동으로 돌고, 결과는 GitHub Pages 주소로 열립니다.
컴퓨터가 꺼져 있어도 상관없고, 폰·태블릿 어디서든 링크로 보시면 됩니다.

---

## 어떻게 '새로 등록된 건'을 알아내나

국토부는 **신고일(공개 등록일) 필드를 제공하지 않습니다.** 계약일만 줍니다.
대신 데이터가 매일 갱신되므로, 매일 같은 범위를 조회해 스냅샷을 남기고
**전일 스냅샷에 없던 레코드 = 새로 등록된 건**으로 판정합니다.
아실·호갱노노 같은 서비스의 '오늘 실거래'도 같은 방식입니다.

그래서 **첫 실행은 반드시 '신규 0건'** 입니다. 비교 대상이 없으니까요.
두 번째 실행부터 실제 신규 등록분이 채워집니다.

---

## 설치 (한 번만)

### 1. 저장소 만들기

GitHub에서 새 저장소를 만듭니다. **Public**으로 두세요
(무료 플랜에서 GitHub Pages를 쓰려면 공개여야 합니다. 담기는 건 국토부가 이미 공개한
실거래 데이터라 민감한 정보는 없고, 인증키는 아래 Secret에 따로 보관되어 노출되지 않습니다).

이 폴더의 파일 전부를 저장소에 올립니다.

### 2. 인증키를 Secret으로 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

- Name: `MOLIT_SERVICE_KEY`
- Secret: 공공데이터포털 **일반 인증키(Encoding)** 값

### 3. Actions에 쓰기 권한 주기

저장소 → **Settings** → **Actions** → **General** → 맨 아래 **Workflow permissions**
→ **Read and write permissions** 선택 → Save

(리포트와 스냅샷을 저장소에 커밋해야 하기 때문입니다.)

### 4. GitHub Pages 켜기

저장소 → **Settings** → **Pages**
→ Source: **Deploy from a branch** → Branch: **main** / **/ (root)** → Save

몇 분 뒤 `https://<사용자명>.github.io/<저장소명>/` 주소가 살아납니다.

### 5. 첫 실행

저장소 → **Actions** 탭 → 왼쪽에서 **실거래 등록 브리핑** 선택
→ 오른쪽 **Run workflow** 버튼

5~10분 걸립니다. 끝나면 `index.html`, `summary.md`, `prev_snapshot.json.gz`가
저장소에 커밋되어 있어야 합니다. 첫 실행은 '신규 0건'이 정상입니다.

## 매일 무슨 일이 일어나나

```
06:30 KST   GitHub Actions 가 국토부 API 조회 → 전일 스냅샷과 대조
            → index.html (리포트) + summary.md (요약) 커밋
07:00 KST   Claude 예약 작업이 summary.md 를 읽어
            채팅 요약 + 푸시 알림 발송
```

- `index.html` — 리포트 본체. Pages 주소로 열립니다.
- `summary.md` — Claude가 읽는 압축 요약본.
- `prev_snapshot.json.gz` — 다음 날 대조에 쓸 스냅샷. **지우지 마세요.**

## 설정 바꾸기

`config.json`에서:

| 항목 | 설명 |
|---|---|
| `regions` | 조사할 시군구 (법정동 코드 5자리) |
| `bands` | 가격 구간, 단위는 만원 (`105000` = 10억 5천만원) |
| `history_months` | 직전거래 비교용으로 거슬러 올라갈 개월 수 |
| `diff_months` | 신규 판정 대상 기간. 신고기한이 계약 후 30일이라 3이면 충분 |
| `redevelopment_watchlist` | 재건축·재개발 단지와 진행 단계 |

정비사업 표시는 워치리스트 매칭에 더해 **준공 30년 경과 단지를 자동 감지**합니다.

## 문제가 생기면

**Actions가 빨간색으로 실패** — Actions 탭에서 로그를 보세요.

- `HTTP Error 429` — 호출이 몰린 것. 워크플로가 2분 뒤 한 번 재시도합니다.
  계속 실패하면 `config.json`의 `history_months`를 6으로 줄이세요.
- `모든 요청이 실패` — Secret에 넣은 인증키를 확인하세요.
- `일부 구간이 빠진 채로...` — 의도된 중단입니다. 데이터가 빠진 채 스냅샷을 저장하면
  다음 날 그 거래들이 전부 가짜 '신규'로 잡히기 때문에, 저장하지 않고 멈춥니다.
  Actions 탭에서 다시 실행하면 됩니다.

**리포트가 매일 '신규 0건'** — 스냅샷이 커밋되지 않고 있을 가능성이 큽니다.
위 3번(Read and write permissions)을 확인하세요.

## 데이터에 대해

- 금액은 **신고서 기준**이며 등기 완료 여부와 다릅니다.
- **계약해제** 건은 취소선으로 표시됩니다. 신고가를 띄웠다가 취소하는 거래를 걸러 보세요.
- **직거래**는 거래유형 칸에 표시됩니다. 특수관계인 간 거래일 수 있어 시세로 해석할 때
  주의가 필요합니다.
- 상승은 빨강, 하락은 파랑입니다 (국내 시장 관행).

투자 판단의 근거로 쓰기 전에 반드시 원본을 확인하세요.
